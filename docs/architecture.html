CockroachDB · the memory
fact BITEMPORAL
valid_from / valid_to is when the claim is true in the world. asserted_at / retracted_at is when this system believed it. A claim is never updated in place: v1 is retracted and v2 asserted beside it, in one transaction.
believed BOOL AS (retracted_at IS NULL) STORED
VECTOR INDEX fact_semantic (believed, embedding vector_cosine_ops)
decision → decision_read
What the agent said, and the exact claim version it read, written in the same transaction as the answer. No code path stores an answer without its provenance.
correction · outbox · memory_audit
The repair, the notice, and the audit line, all committed with the change they describe. The outbox key is a hash of the correction, so a replayed sweep is a no-op.
9 nodes · 3 regions · SURVIVE REGION FAILURE LOCAL ONLY
5 replicas placed so no single region holds a majority. patient is REGIONAL BY ROW, so residency is enforced by storage rather than by application code. The hosted demo is CockroachDB Cloud Basic, which is single-region, so it reports a zone survival goal. Multi-region is an Advanced-tier feature; this topology is the local docker compose cluster.

The retroactive repair loop
1 · INGEST
A claim changes
The FDA escalates a lot. v1 retracted, v2 asserted under the same key, one transaction.
2 · SQL
Find what depended on it
decision → decision_read → fact where the answer still stands, the read was load-bearing, and the version it read is now retracted.
3 · BEDROCK
Re-decide each one
Against what is believed today, not against what was believed then.
4 · COCKROACHDB
Repair, or leave alone
Verdict changed: correction plus outbox notice, one transaction. Unchanged: reaffirmed, and deliberately not messaged.
5 · REPLAY
Answer at any past instant
Bitemporal reconstruction still answers at 45 days, where AS OF SYSTEM TIME has hit the GC threshold.

Demo scenario, measured on the hosted cluster: 12 standing answers examined, 9 reversed and notified by name, 3 reaffirmed and not messaged, in under 5 seconds.
